# Windows 手动验收

必须在安装依赖并成功编译后执行。仅通过源码检查或浏览器预览不能验证原生行为。

## 本机验证记录

- 2026-10-13：9 个 Rust 测试和 2 个 Node 测试通过；Clippy、前端类型检查与 ESLint 通过。Windows 构建成功，真实 Codex 额度读取、点击展开、滚轮和按钮缩放已测试。
- 用户手动检查拖动和宿主窗口移动、最小化、还原后反馈“没什么异常”。这不代表混合 DPI、多显示器、双主窗口等所有场景已验收。
- 外观更新：使用用户第 3 张参考图的人物，思考气泡改为白底粗描边。浏览器使用明确的示例数据检查双额度、金色低额度提示、错误状态和设置页；临时示例入口已移除，不进入正式构建。截图见 [appearance-preview.png](appearance-preview.png)，截图内 30% / 14% 为示例值。
- 2026-10-14：新版 Release EXE 离线构建并启动成功。原生窗口已确认人物透明背景、点击展开新气泡、读取真实额度，并保留原有 80% 缩放和跟随位置。类型检查、ESLint 与 Node 测试通过；本轮未修改 Rust 跟随实现。
- 2026-10-14（倒计时与动效）：重置倒计时移至百分比左侧，字号由 8px 调至 12px，格式为 `3d6h23m`；原生窗口底部显示 `HH:mm 更新`。人物按下压扁、松开弹性回弹，达到拖动阈值或失焦时取消按压动画。浏览器验证重复点击、键盘 Enter、动画结束恢复原形及布局无溢出；原生窗口确认真实倒计时和更新时间。3 个 Node 测试、前端类型检查、ESLint、Vite 构建及离线 Release 编译通过；没有安装或下载依赖。原生拖动和跟随本轮未重新做完整验收。

| 操作 | 预期 |
| --- | --- |
| Codex 未启动时运行挂件 | 只出现托盘图标，无白色窗口闪烁；“显示在桌面”可恢复显示 |
| 打开 Codex，托盘选择跟随 | 角色出现在 Codex 右下角；不抢键盘焦点 |
| 点击角色 / 键盘聚焦后按 Enter | 压扁后弹性回弹，打开气泡；再次点击可收起并重新播放动效 |
| 查询额度 | 与同账户 Codex 实际额度一致；没有额外聊天或模型请求 |
| 退出登录、API Key 登录、断网 | 明确错误；不显示上个账户的额度，不把失败显示成 0% |
| 拖动角色至少 5px | 移动角色，不触发点击开关；松开后保存相对位置 |
| 移动、缩放、最大化 Codex | 角色跟随并保持相对右下角偏移 |
| Codex 最小化、隐藏、关闭 | 角色隐藏，定时额度刷新暂停，托盘仍可用 |
| 用其他窗口遮挡 Codex | 角色一同被遮挡，不浮到其他窗口上方 |
| 点击角色和气泡以外的位置 | 点击到后方应用，不被透明大矩形阻挡 |
| 60% / 100% / 160% 缩放 | 角色、气泡、点击区域一致，无裁切或明显错位 |
| 100% 与 150% / 200% DPI 屏幕间移动 | 角色尺寸与坐标正确，气泡可交互 |
| 两个 Codex 主窗口 | 优先跟随激活的 Codex 窗口；切换其他应用时保持原目标 |
| 桌面模式拖到第二屏，重启应用 | 恢复保存位置；第二屏断开后仍可找到角色 |
| 修改 CLI 路径时有查询进行中 | 旧请求结果不覆盖新配置，新路径会重新查询 |
| 重复启动 / 托盘重置 / 退出 | 无多个实例；能重置位置；正常退出后查询子进程被回收 |

特别记录：Windows 版本、Codex 版本、显示器 DPI、出现异常时的操作。不要收集或提交登录令牌、账户邮箱、原始 App Server 响应。
